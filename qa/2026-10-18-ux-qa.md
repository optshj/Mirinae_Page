## 시나리오별 결과

### S1. 홍보글 → 데스크톱으로 바로 다운로드 (Windows, 1440×900)

1. 진입 → 별 배경 + 헤드라인. **로드 직후 다운로드 버튼이 없다**([01](./2026-10-18/01-hero-on-load.png)). 약 2.5초 뒤 페이드인.
2. "Windows용 다운로드" 클릭 → exe 다운로드 시작 + "다운로드 중이에요!" SmartScreen 안내([04](./2026-10-18/04-download-dialog.png)). ✅ 친절함.
3. 헤더/하단 CTA도 동일하게 동작. ✅

- 문제: **C4, M4, M5**

### S2. 노트북 사용자 (1366×768, 1280×720, 1920×1080)

- 히어로 CTA y=440/416/596 → 모두 첫 화면 안. ✅ ([12](./2026-10-18/12-laptop-1366.png))

### S3. 회사·학교·PC방 등 공유 IP 사용자 (GitHub API 레이트리밋 403 재현)

1. 다운로드 링크를 GitHub API에서 가져오는데 실패 → `href="#"` 유지.
2. 버튼 클릭 → **`download.htm`(현재 페이지 HTML)이 다운로드**되고, 화면엔 "다운로드 중이에요!"가 뜸([05](./2026-10-18/05-ratelimit-dialog.png)).
3. 콘솔: `Cannot read properties of undefined (reading 'find')` — 에러 응답을 검사하지 않음.

- 문제: **C2**

### S4. 느린 네트워크 (3G 수준: 400ms 지연, 400kbps)

- CTA가 보이기까지 **19.1초**, 실제 다운로드 링크가 붙기까지 19.7초.
- 문제: **M4**

### S5. 창을 반만 쓰거나 200% 확대한 Windows PC 사용자 (뷰포트 700px / 720px)

- 클릭 → 다운로드 없이 **"PC에서 다운로드해주세요"**([06](./2026-10-18/06-narrow-desktop.png)). 이미 PC인데 갈 곳이 없음. 저시력 사용자(확대)·분할 화면 사용자가 그대로 이탈.
- 문제: **C3**

### S6. Mac / iPad 사용자

- Mac(Chrome): exe 다운로드 + Windows SmartScreen 안내. 실행 불가 파일을 받고 나서야 알게 됨.
- iPad 820(세로)/1180(가로): 동일하게 exe 다운로드 시도 + SmartScreen 안내([07](./2026-10-18/07-ipad.png)). PC 전용 안내가 뜨지 않음.
- 문제: **M1**

### S7. 카카오톡 인앱 브라우저로 링크 열람 (iPhone, 클립보드 권한 거부 재현)

2. "복사하기" 탭 → 복사 실패. **화면 변화 없음**, 콘솔에 Unhandled rejection(`PAGEERROR denied`)([08](./2026-10-18/08-kakao-copy-fail.png)). 사용자는 복사된 줄 알고 PC에서 붙여넣기 → 빈 클립보드.

## 이슈 목록

### 🔴 Critical

**C1. 링크 공유 썸네일·canonical이 죽은 도메인을 가리킴** — ✅ 수정됨 (2026-10-18, 전 파일 `mirinae.today`로 치환 + `/updates`·`/bug-report`에 og:image·twitter 카드 추가. 로컬 렌더 HTML에서 5개 페이지 모두 확인. `/privacy-policy` og:url은 루트 상속 그대로 — noindex라 보류)

- 현상: 카톡/디스코드/커뮤니티에 링크 공유 시 썸네일 없음. 검색엔진 canonical도 존재하지 않는 도메인.
- 근거: `curl: (6) Could not resolve host: www.mirinaecalendar.store`. 이미지 자체는 `https://www.mirinae.today/ogImage.webp` 200.
- 위치: `src/app/App.tsx`(홈 메타데이터), `src/pages/Docs/ui/DocsPage.tsx`, `app/docs/page.tsx:10,15,21,32`, `app/bug-report/page.tsx:8,13`, `app/privacy-policy/page.tsx:8`, `app/updates/page.tsx`, `app/robots.txt:5`, `app/sitemap.xml`
- 제안: `mirinaecalendar.store` → `mirinae.today` 일괄 치환. `app/layout.tsx`에 `metadataBase` 지정 후 하위는 상대경로로. `/updates`·`/bug-report`에도 og:image.

**C2. 다운로드 URL 조회 실패 시 `download.htm`이 받아짐** — 🟡 완화됨 (2026-10-18, `useDownloadUrl` 기본값을 `'#'` → GitHub `releases/latest`로. API 403 시 릴리스 페이지로 이동 확인. 서버에서 URL 결정하는 근본 해결은 미진행)

- 현상: GitHub API(비인증 60회/시간/IP) 레이트리밋·장애·느린 응답 시 `href="#"` + `download` 속성 → 페이지 HTML이 `download.htm`으로 저장되고 "다운로드 중이에요!" 안내가 뜸. 공유 IP(학교·회사·PC방)에서 재현 가능성 높음.
- 위치: `src/features/download/lib/useDownloadUrl.ts` (`data.assets` 존재 검사 없음, 초기값 `'#'`), `src/features/download/ui/DownloadButton.tsx:20-21`, `DownloadButtonHeader.tsx`
- 제안: 초기값/실패 폴백을 `https://github.com/optshj/Mirinae/releases/latest` 로. 더 나은 방법은 클라이언트에서 API를 부르지 말고 서버(ISR/`revalidate`)에서 URL을 정해 HTML에 넣기 → C2·S12·M4(링크 부분) 동시 해결.

**C3. 창이 좁거나 확대한 Windows PC 사용자가 다운로드할 방법이 없음** — ✅ 수정됨 (2026-10-18, UA 기반 판별로 교체. 로컬 검증: Windows 1440/700px/200%·터치 노트북 → 다운로드, iPhone/Android/iPadOS → PC 안내)

- 현상: 기기 판별이 화면 너비(`max-width: 767px`)라서, PC에서도 창 폭 <768px이면 "PC에서 다운로드해주세요"만 뜨고 다운로드 불가. 200% 확대 사용자도 동일.
- 위치: `src/features/download/lib/useIsMobileDevice.ts:3`
- 제안: 너비 대신 `(pointer: coarse)` + UA(`/Android|iPhone|iPad|Mobile/`) 기준으로 판별. 최소한 PC 전용 다이얼로그에 "그래도 다운로드" 링크 추가.

### 🟠 Major

**M1. Mac·iPad 사용자에게 exe 다운로드 + Windows 설치 안내** — ✅ 수정됨 (2026-10-18, `useDeviceOs`로 OS 판별. Windows 외 전부 "Windows PC에서 다운로드해주세요" + 링크 복사. Mac/Linux 클릭은 `unsupported_os_download_click { location, os }`로 수집. 알림 신청은 백엔드 필요로 보류)

- 위치: C3과 동일(너비 판별). Mac은 너비가 넓어 데스크톱으로 판별, iPad(820/1180)도 768 이상이라 데스크톱.
- 제안: OS 판별(`navigator.userAgentData.platform` / UA)로 Windows가 아니면 "현재 Windows만 지원" + 링크 복사/알림 신청 다이얼로그. Mac 수요 측정용 `posthog.capture('unsupported_os_download_click', { os })` 추천.

**M2. 링크 복사 실패 시 무반응 (인앱 브라우저)**

- 위치: `src/entities/decription/ui/PCOnlyDescription.tsx:16` — `writeText` try/catch 없음.
- 제안: 실패 시 주소 텍스트를 선택 상태로 만들고 "길게 눌러 복사해주세요" 안내. 카톡 유입 비중이 높을 홍보 채널 특성상 중요.

**M3. FAQ가 키보드로 열리지 않음**

- 위치: `src/widgets/Section/ui/Section3.tsx:80-86` — `motion.div`에 `onClick`.
- 제안: 질문 영역을 `<button aria-expanded>`로, 혹은 네이티브 `<details><summary>`.

**M4. 핵심 CTA가 늦게 등장 (일반 2.5초, 3G 19초)** — ✅ 수정됨 (2026-10-18, 히어로 CTA 애니메이션 제거로 SSR HTML에서 바로 노출 + 히어로 `MotionConfig reducedMotion="user"`. 프로덕션 빌드 기준 3G에서도 CTA 0.7초 노출)

- 원인: 히어로 CTA가 진입 애니메이션 딜레이 + 클라이언트에서 링크 주입.
- 제안: 히어로 CTA는 애니메이션 없이(또는 delay 0) 렌더. `prefers-reduced-motion` 존중.

**M6. 제보 이미지 삭제 버튼이 터치 기기에서 안 보임**

- 위치: `src/pages/Bug-Report/ui/BugReportPage.tsx:142-148` — `opacity-0 group-hover:opacity-100`, `aria-label` 없음.
- 제안: 모바일 기본 노출(`opacity-100 md:opacity-0 md:group-hover:opacity-100`) + `aria-label="이미지 삭제"`.

**M7. 첨부 이미지 용량 제한 없음 → 큰 스크린샷은 실패할 가능성 (추정, 미재현)**

- 근거: Vercel 서버리스 함수 요청 본문 한도 4.5MB, Discord 웹훅 첨부 한도 존재. 클라이언트·`app/api/bug-report/route.ts` 모두 크기 검사 없음 → 고해상도 스크린샷 2~3장이면 일반 "오류" 메시지만 보고 원인 모름. 실제 전송 위험 때문에 프로덕션 재현은 하지 않음.
- 제안: 클라이언트에서 합계 용량 검사 + 캔버스 리사이즈/압축, 413일 때 별도 메시지.
- 참고(보안): `/api/bug-report`는 인증·레이트리밋 없이 Discord로 그대로 전달 → 스팸 경로.
